# 普通与动态线段树

本页只讲 SegTree 与 DySegTree; 主席树、合并分裂和泛型插件另行验证。
两份源码尾部都有可运行的区间加、区间和/最大值 Usage。

| 场景 | 使用方式 |
|---|---|
| 已知长度的稠密数组 | SegTree(max_n), init(n) 后 build(a); 后续重建仍先 init |
| 很大值域, 初始全零 | DySegTree(n, budget), 不必 build, 按操作按需开点 |
| 动态树多测 | clear 保留值域; init(n) 清空并改值域; build(a) 自带清空并设 n=a.size()-1 |
| 静态区间最值 | [ST 表](../ST表/ST表.cpp) build(a, true/false), O(1) 查询 max/min; 更新需重建 |

数组 a[0] 不参与建树; 值域与修改/查询区间必须非空, 区间合法且数值运算不溢出。
Info{} 为合并单位元, len=0; 动态版将虚区间的 len 补为真实长度后, 其余默认字段必须表示初始零值区间。
例如维护最大值时虚区间 mx=0, 合并时先判 len=0, 不能让空单位元把全负区间的最大值抬到 0。

Tag::apply 把新操作接到旧操作之后, 赋值与加法等操作不能随意交换。
普通懒标记提供恒 false 的 break_cond 和恒 true 的 tag_cond;
势能修改由前者判无需修改, 后者判整段可施加标记, 叶子必须能终止。
可选 get_real_tag 将修改请求转成实际懒标记, split_tag 负责向左右孩子分发。
局部等差标记跨查询端点的偏移仍由代数层负责, 引擎不会自动把每个覆盖段换算为修改左端点。

find_first(start, pred) 与 find_last(end, pred) 找的是符合条件的点。
pred 必须等价于“这段里存在答案”, 例如 mx >= k; 区间和 >= k 不具有一般的存在性含义,
也不会在遍历中累积前缀。找不到或 start/end 不在 [1, n] 内返回 -1。

动态池按两次复位之间的累计开点数预算, 不按操作数直接当结点数。
build 使用 2n-1 个实结点; 普通懒修改、查询和查找每次可能新增 O(log n) 个,
势能修改按实际访问和开点分析。查询并非只读: 下传旧标记时也可能创建子结点。
复位保留容量并恢复 0 号哨兵, 旧结点编号失效。40 B/结点时 400 万预算约 160 MB。

原 seg_check 已补独立逐点参照、仿射叠加、可选分支及 20 万规模, 无参数自动进入 CI。
具体已验范围和限制见 [P05 记录](../../../records/verification/seg-20260906.md),
