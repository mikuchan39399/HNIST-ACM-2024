# 优化建图 · 路线

用数据结构结点代替区间连边: 单点连区间、区间连区间, 边数从 O(n²) 压到
O(n log n), 然后跑最短路 / SCC / 2-SAT。左程云课里叫"三种优化建图"的那批。

## 顺序

基础: 拆点、分层图、虚点(超级源汇) —— 手法层, 写几道例题就有手感
核心: 线段树优化建图 —— 出边树加入边树各一棵, 经典题 CF786B Legacy;
内存紧就换动态开点版
然后: 2-SAT 优化建图(线段树优化蕴含边, 配 SCC) 和 2-SAT 前缀优化建图
最后: 主席树优化建图(历史版本连边)、CDQ 优化建图(时间维分治连边)

## 入库形态

应用件流水线: 每个套路一篇组装范例(完整例题代码加关键行注释)。
现役模板按最终验证要求验收, 独立参照为朴素逐点展开的图, 不复用线段树分解。
差分约束和同余最短路在最短路问题\ 那边, 不在这。

## SegGraph 的两棵树

出树的零权边从父结点到儿子, 从某个覆盖结点能到达它表示的全部原点;
入树的零权边从儿子到父结点, 区间内原点能到达表示该区间的覆盖结点。
两树仅共用叶子编号 1 .. n, 因此骨架本身不会让不同原点互相可达。
单点连区间与区间连单点只需连 O(log n) 个覆盖结点。

区间连区间时新建一个中继点, 源区间先以零权连入, 再以 w 连向目标区间,
所以每条被压缩的逻辑边恰好贡献一次 w, 不会把两端都算成 w。
add_r2new / add_p2new 返回的中继点可继续作为单点参数连边;
区间参数始终指原点区间, 不能拿虚点编号当区间下标。

## 容量与组装

构造为 `SegGraph<W>(max_n, max_m, max_extra)`:

- max_n 是原点上限, build(n) 要求 1 <= n <= max_n; 不支持空区间或 build(0)。
- max_extra 是单轮新增中继点上限, 默认 -1 表示取 max_n。r2r、r2new、p2new 每次各用一个,
  三者次数之和不超过它。q 远大于 n 时应显式传入, 预算耗尽在新建中继点处断言。
- max_m 只是边预留提示, 可以取 0 让边数组自动增长。两参数旧写法仍可用,
  但不能把边容量当成中继点容量; Graph 本身的点表不会自动增长。
- build 后有 3n-2 个点、4n-4 条骨架边。令 L=max(1,ceil(log2 n)),
  p2p/p2new 每次 1 条边, p2r/r2p/r2new 每次至多 2L 条, r2r 每次至多 4L 条。
  按各类操作次数相加即可估计 max_m, 还需另算下游算法的内存。
- 反复 build 自动清掉旧图并恢复新增中继预算, 旧虚点编号全部失效。

最短路算法应按 sg.tot 分配和初始化, 在 sg.g 上运行, 输出时通常只取 1 .. sg.n。
不能使用 sg.g.node_cnt() 代替 sg.tot: Graph 的该接口不计孤立点, n=1 且无加边时尤其明显。
非负权可接 Dijkstra, 本库不可达哨兵为 INF, 要求有效最短距离小于 INF 且加法不溢出。
SegGraph 自身只是建图, 负权须交给适用的最短路算法; 无权可用 SegGraph<Empty> 接可达性或 SCC,
Empty 的骨架边不能当成“走一条就加一”的原图距离。

## 当前验证

已有套件保留原 300 组随机测试, 新增 400 组独立 Floyd 全点对、Empty 的实际可达性与 SCC 组装,
覆盖原点和用户中继点作源, 零权、重边、自环、重叠区间、单点和完整区间、负权 DAG 及接近 INF 的距离。
默认还跑 20 万点/操作、非对齐区间、多测重建、32 点 SCC 分块及仅 1/2 个原点时新建 20 万虚点。
这些都在无参数 seggraph_check 内, 普通与 sanitizer CI 自动执行, 无额外手动验收模式。
这里仅验证 SCC/Dijkstra 与 SegGraph 的相应组合, 不代表两个下游算法的全部接口已验收。
