# 自己移动目录、增加算法

[返回维护说明](README.md)

可以直接移动已经登记的算法源文件。保留第一行 `// zoi: 短名`，下一次展开、对拍、生成手册、生成跳板或打包时，入口先运行路径同步。无需常驻监听，也不需要 LLM 逐份修改路径；同步器只依赖 PowerShell 5.1/7。

## 平时怎么做

移动源文件或改中文文件名后，照常使用上述入口。想立即同步或只检查时，在库根运行：

```powershell
./scripts/sync_layout.ps1
./scripts/sync_layout.ps1 -Check
```

同步会更新 catalog、跳板、可识别的本地 include、现有 Markdown 链接和验证登记中的路径；有变更时再刷新算法目录、测试资产表和验证表。静态 Markdown 不会在资源管理器刚移动文件的瞬间变化。`-Check` 不写文件，发现待同步内容会失败；`-NoRefresh` 只同步路径，不刷新三份生成入口。

新增可调用模板时，给源码一个唯一且稳定的短名：

```cpp
// zoi: myAlgorithm
#ifndef Z_OI_MY_ALGORITHM
#define Z_OI_MY_ALGORITHM
// 实现、必要依赖和完整 Usage
#endif
```

同步器据此登记实际路径并生成 `myAlgorithm.h`，不再要求先手填同一份路径到 catalog。复制已有模板时必须改短名和守卫。普通测试取名 `*_check.cpp`，放进 `algorithms` 下就会进入默认测试扫描；测试代码和独立参照仍由人编写。

新笔记的 `^短名`、不配跳板的 `!豁免` 仍在 catalog 显式登记，避免把练习和草稿都变成正式模板。新增 README 仍按用户选择，不自动创建。新增或撤下算法后，学习表、设计分类与有意义的验证范围仍需维护；CI 会提示缺项，不会猜测这些内容。

## 哪些地方依赖目录

这里按十二个子系统计数，不把测试夹具、历史证据里的每个路径字符串算成一个系统。改造前，四项本来就自动扫描，六项需要同步具体路径，另两项承载应由人决定的配置。路径本身仍会出现在生成文件和 C++ include 中；本次消除的是重复手工维护。

| 子系统 | 原先的机制 | 现在移动目录后的行为 |
|---|---|---|
| 默认对拍发现 | 递归扫描 `*_check.cpp` | 本来自动；不额外填写 suite 列表 |
| 依赖与测试指纹 | 遍历本地依赖并计算哈希 | 本来自动；移动或修改后旧证据不能冒充当前通过 |
| 手册章节树 | 扫描真实目录与源文件 | 本来自动；先同步它引用的 catalog 和 include |
| 队友包文件收集 | 在规定发布根下递归收集 | 本来自动；先同步再检查并打包 |
| 引擎 catalog | 短名对应手填路径 | 按源码第一行的稳定短名更新；新短名自动登记 |
| zoi 跳板 | catalog 生成固定 include | 同步路径时自动重建相应跳板 |
| C++ 本地 include | 依赖文件的相对路径 | 根据迁移前后位置修正，跳过注释和 raw string |
| 验证范围里的文件路径 | template、suite 手填路径 | 模板按短名；已登记 suite 按唯一文件名迁移；覆盖含义不变 |
| 现有文档链接及派生目录 | 链接路径、生成结果可能过期 | 修正受支持链接，再调用已有生成器；不改历史运行 JSON |
| BigInt/rw 和图论专项压力入口 | 源码所在家族目录写在脚本里 | 按引擎短名、唯一测试文件名定位，不依赖家族层级 |
| 学习、设计、验证范围、README 选择 | 人判断含义与归属 | 保留人工决定；只迁移已有链接，不新增臃肿列表 |
| 工具入口、发布范围、豁免、额外 CI profile | 固定协议和有意选择 | 保留显式配置；增加特殊压力参数仍要接入 CI |

实现入口：[同步器](../../scripts/sync_layout.ps1)、[资产扫描](../../scripts/check_inventory.ps1)、[手册树](../../scripts/booklet_tree.ps1)、[路径定位](../../scripts/source_lookup.py)。

## 自动处理的边界

- 引擎可以移动并改文件名，短名不变即可。已登记笔记和 suite 没有源码短名，只有旧路径消失且文件名唯一时才迁移；同时改文件名需要显式改登记。
- 删除、合并、替换、短名改名不是单纯移动：需要调整接口和登记。不能从文件消失猜出它被并入哪份代码。本次两个数值小件就是明确合并到 utils，旧 `intSqrt.h`、`divCeilFloor.h` 已撤下，调用方改用 `utils.h`。
- 只处理能从已登记旧路径确定目标的直接双引号 include；宏 include、外部工程中的中文相对路径、未登记文件自身被移动后的相对依赖，以及被一起移动的 README 内部相对链接，必要时仍须人工修正。使用短名跳板的外部题解不受引擎位置变化影响。同步之后的编译和文档检查负责暴露剩余问题。
- Markdown 支持本库常用的普通/尖括号内联链接与引用定义，跳过代码块、行内代码和注释。链接文字不会被自动改写；历史报告只维护可点击目标，原始运行 JSON、压力证据和规则原文快照不重写。
- 不扫描私人缓存、发布输出和恢复备份，不跟随链接。重复短名、歧义 include、找不到或重名的已登记目标会停止，写入前完成检查；普通 I/O 失败尝试回滚。不要同时让多个进程移动或同步同一批源码。
- 原有独立 `-Check` 生成检查仍然只读。CI 在各工作副本先同步再执行检查，修复不会自动提交回 GitHub。直接运行 Python 专项压力脚本前先同步一次，它的定位器只负责找文件。

## 自检

```powershell
python scripts/check_layout.py --shell powershell
python scripts/check_layout.py --shell pwsh
```

夹具覆盖跨层移动、真实 include 编译、反向链接、中文/空格路径、只读与幂等、新短名、笔记迁移、重复和歧义拒绝、历史证据保留。测试现场由入口验证归属后清理。CI 普通作业运行同一套测试。
