# Booklet 系统说明

[使用与打印](README.md) · [工具维护](../maintenance/README.md) · [模板契约](../../rule.md)

## 两种使用场景

| 场景 | 入口与约定 |
|---|---|
| 日常训练、展开提交 | 引用原来的短名头文件；不定义 `ZOI_BOOKLET`。按各模板现有的字符串、占位数组与 span 契约调用 |
| 纸质赛场模板 | 固定 C++20，生成器将 `ZOI_BOOKLET` 视为已定义；只保留适合抄写的接口和 Usage |

当前 KMP、Manacher、ZFunction 的纸版只传 span，省去 string/vector 重载、旧标准分支和内部输入转发层；结果语义与电子版一致。电子版三者仍支持 C++11 起的既有调用。utils 选择 C++20 的头文件、inline 变量及折叠表达式。其他模板按源码本身的契约打印，不能据此推断整库都支持 C++11。

源文件是唯一实现来源。两种接口在原 cpp 中显式分支，算法循环共用；没有独立纸版算法文件、函数名匹配表或字符串替换配方。**自动化负责按明确规则选择源码，不会猜测任意 C++ 包装是否可以删除，也不自动给全部模板增加旧标准兼容。** 后续兼容需求仍由用户逐项提出。

## 一次构建怎样完成

```text
make_booklet.ps1（完整构建）或 build_booklet.ps1
  → 隔离目录
  → 扫描真实目录树、catalog、同目录 README、代数插件
  → 源码中的纸版选择 + C++20 版本选择
  → 展开私有实现头，公共依赖改为短名 include
  → 最终代码 / 行数 / SHA256 / 选择记录
  → 各册 .typ、.code.md、PDF 与 chapters.json
  → 检查真实打印代码与 PDF
  → 更新正式分册，最后写入完整清单
```

完整入口统一由 `build_booklet.ps1` 编排。`make_booklet.ps1` 无参数调用会转入它，旧 VS Code 任务仍然有效；内部使用 `-GenerateOnly` 调用底层生成器，避免递归。筛选预览与 `-SourceOnly` 只生成选定内容，不冒充完整验收。

在源码选择、编译或检查阶段失败，不更新正式输出，隔离目录留作诊断；成功后删除本次隔离目录。发布只清理旧清单登记、但新清单已撤下的生成文件，保留其他文件；目录改名不会留下旧册。发布采用逐文件复制、最后写清单，**不承诺磁盘故障或复制中断时整目录原子替换**。中断后重新完整构建；读取当次清单，不把未列出的文件视为本次产物。现有清单格式或路径异常时停止发布。生成过程不改电子源码。

## 可直接核对的输出

每册保留三个文件：

- `.pdf`：赛场打印内容，不放构建过程说明。
- `.typ`：交给 Typst 的完整排版输入，代码 raw 块、行数和短指纹可直接追溯。
- `.code.md`：可阅读的最终 C++ 代码，附原始源码路径、完整 SHA256、行数和条件选择记录。代码与 `.typ` 的实际 raw 块逐项核对。

`chapters.json` 列出本次完整章节及上述文件，标明 `profile: "contest"`、`cppStandard: "c++20"`。完整入口全部检查成功后才写入 `validation` 字段及检查时间；仅生成产物的清单没有该字段。选择记录列出解析过程中各条件组的求值结果，包含最终被外层分支排除的内层条件；最终代码块才是实际入册内容。

指纹对应最终代码的 UTF-8 字节（换行统一 LF，不含末尾换行），不包括同目录 README。它用于核对内容身份，不是正确性证明。生成物不提交 Git，不能手改生成物来修复源码问题。

## 源码选择协议

保留宏 `ZOI_BOOKLET` 仅用于纸版接口、输入下标适配和 Usage。普通 C++ 编译不定义它，沿用电子版。典型结构如下：

```cpp
#ifdef ZOI_BOOKLET
    void build(auto s)
    {
        int n = int(s.size());
#else
    template<class Seq>
    void build_seq(const Seq& s, int first)
    {
        int n = max(0, int(s.size()) - first);
#endif
        // 两种入口共用算法循环；只在实际不同的表达式处选择输入适配。
    }
```

保持分支粒度小，不复制整份算法。纸版中 `auto` 是 C++20 简写函数模板，调用约定为显式传 span，避免按值复制 string/vector；`span(a).subspan(1)` 跳过占位。span 本身不拥有输入，必须在调用期间有效。

选择器支持：

- `#ifdef ZOI_BOOKLET`、`#ifndef ZOI_BOOKLET`，以及 `#if/#elif defined(ZOI_BOOKLET)` 或 `!defined(ZOI_BOOKLET)`；`defined` 的括号可省略。
- `#if/#elif __cplusplus >= 202002L` 这类直接比较，支持六位十进制版本值、可选 `L/l`、`>= <= == != > <`，固定按 `202002L` 求值。
- 多层嵌套、`#else/#endif`。同一条 `#elif` 链中已知条件可以组合，但不能混入 `LOCAL` 等未知条件。

每条指令独占一行。涉及上述保留宏的逻辑组合、其他表达式、重定义/取消定义、续行、分支结构不完整会报错；需要同时判断普通宏时分层嵌套。选择器是受限规则解析器，不是完整 C++ 预处理器。

头文件保护、`LOCAL` 等未知宏原样保留，只处理其内部已知的纸版/语言版本条件。普通注释、字符/字符串及原始字符串中的伪指令不处理；`/* Usage ... */` 单独按同一规则选择。README 与登记笔记不做 C++ 裁剪。标准库不展开，普通宏不求值。

每个文件先选择分支，再读取选中的私有 `.h`；死分支的 include 不打开，循环引用或无法解析的路径报错。公共 catalog 依赖保留短名。**交题展开器仍不支持条件本地 include**：公共依赖和 Usage 的 include 放在选择分支外，不为打印改变展开契约。不凭 `_legacy` 等文件名推断是否应丢弃。

## 自动发现与人工维护的边界

| 项目 | 如何维护 |
|---|---|
| 章节、子目录、待建目录 | 从 `algorithms/` 自动扫描；排除对拍及隐藏工具目录；按实际一级目录分册 |
| 现役实现、笔记、短名和既有排序 | 沿用 catalog 与源码短名同步机制；多个实现分别入册 |
| 源码同目录 README | 自动发现，共享说明只跟随最后一份选中实现；是否创建仍由用户决定 |
| 代数插件 | 自动发现所属目录内不带实际 main 的 cpp |
| 纸版接口与条件 | 维护模板自身的 `ZOI_BOOKLET` 分支，生成器不登记算法名字 |
| 算法行为验证 | 维护者选择独立参照和边界用例；新纸版适配必须接入实际打印代码测试 |

新增需要适配的模板时，先确认电子接口和目标旧标准，在源码中保留共用算法、标明纸版差异及完整 Usage；生成后检查纸版无兼容转发残留，再分别验证电子版与实际纸版。普通算法源码修改会自然进入下一次构建，不必同步函数签名锚点或另写打印配置。

## 验证范围与实现入口

| 文件 | 职责 |
|---|---|
| `scripts/build_booklet.ps1` | 完整构建、依赖预检、打印代码/PDF 验证及最终发布 |
| `scripts/make_booklet.ps1` | 目录编排、代码与指纹输出、Typst 排版和原生审计 |
| `scripts/booklet_cpp.ps1` | 通用源码选择、选择记录及私有头展开 |
| `scripts/booklet_tree.ps1` | 目录树、排序和筛选 |
| `scripts/booklet_markdown.ps1` | 说明文档的有限 Markdown/数学转换 |
| `scripts/check_booklet_cpp.ps1` | 条件解析、共用正文、Usage、字面量及错误拒绝 |
| `scripts/check_booklet.ps1` | 隔离目录/源码/说明/排版夹具，覆盖 PS5.1/7 |
| `scripts/check_booklet_release.ps1` | 生成/代码/PDF 失败保留旧输出、检查顺序、发布与旧册清理的隔离测试 |
| `scripts/check_booklet_code.py` | 逐项比对可读代码、真实 raw 块、行数和指纹；运行打印代码测试 |
| `scripts/check_booklet_pdf.py` | 独立核对 PDF 目录、页段、文字、公式、A4 版式和页脚 |

当前真实打印代码的行为验证覆盖 **KMP、Manacher、ZFunction（含 E）和 utils**：完整对拍、退化/百万长度重建、span 边界、直接 Usage、空态和底座多翻译单元等。测试适配器 `booklet_test_adapter.h` 只将旧套件输入转成 span，不含算法；Usage 直接编译纸版接口。其他 C++ 条目检查内容与指纹一致性，不能宣称全部印刷模板已做同等行为验收。

电子版另由 `check_submit_bridge.cjs` 验证实际展开后的 C++11/14/17/20/23 代码及旧标准头文件隔离，相关原套件由 `run_checks.ps1` 更新验证表。纸版通过不能替代电子兼容验证。

CI 使用相同完整入口，另外运行生成器的正常/拒绝夹具；附件包含 PDF、Typst、可读代码和清单。字体、封面或布局调整后仍须渲染页面人工检查。详细测试命令见[测试说明](../../scripts/checks.md#手册自动检查)。
