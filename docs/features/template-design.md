# 模板设计分类

换一道题，哪些留下，哪些重写。执行约定见 [rule §3.1](../../rule.md#31-启发式模板-2026-09-07-用户裁决)。

## 怎么判断强弱

| 类型 | 留给选手什么 |
|---|---|
| 固定引擎 | 内核稳定，换参数与代数即可调用 |
| 启发式骨架 | 留下关键公式和循环，状态与贡献现场落笔 |
| 固定内核加题目骨架 | 调度不变，统计与建模按题生长 |

“启发式”指唤起解题思路，不是近似算法。分类是设计方向，不代表已经完成实现或验证。

## 目录颗粒度与分类

目录保留方向、家族与具体算法。**只要算法目录存在，它就在手册里有位置**；待建目录也保留，纯对拍目录除外。同家族实现可以并列存放，目录会收录各源码；不添加分类短题记或中层通用长文。

三类设计是另一维度，不据此搬动源码。路线在 [路线图](../roadmaps/README.md)，个人状态在 [进度表](../progress/README.md)，代码身份在 [catalog](catalog.md)。

## 分块怎么归类

分块是弱模板思路，具体容器可以有固定内核。

| 做法 | 归类与改题处 |
|---|---|
| 普通/值域分块 | 启发式骨架；改整块摘要、散块处理与重建 |
| 根号分治/树上分块 | 启发式骨架；改阈值与轻重分工 |
| 莫队及带修/树上变体 | 固定调度加题目骨架；改增删贡献、回退与查询映射 |
| 块状数组/链表 | 容器内核可固定；附加统计仍随题变化 |

区间加和区间计数可以共用分块思路，却需要不同的块内信息。留下清楚的改法，比塞进一个万能接口更有用。
