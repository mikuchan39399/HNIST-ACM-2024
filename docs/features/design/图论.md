### 优化建图家族的组合设计

现役实现分为共享上下文、压缩结构与应用层。`graphBuilder.h` 提供 `GraphBuilder<W>`，`prefixGraph.h` 提供四种建链函数和兼容封装，`segGraph.h`/`treeGraph.h` 分别提供 `SegLinks`/`TreeLinks` 和兼容封装。2-SAT 的取反规则不进入压缩内核。

`GraphBuilder(max_n,max_m)` 的第一参数是最终整图点容量，包含已有状态点、所有结构辅助点及手动中继；第二参数只预留边。`init(n)` 清图并保留初始点 `1..n`，`new_node()` 分配全局编号；预算不自动扩容。公开 `g/tot` 接下游，`add(u,v,w)` 遇到 0 入口不加边。结构只引用上下文，必须在上下文仍存活且未清空时使用；不要移动仍被引用的上下文。

- 前后缀：`prefix_in/prefix_out/suffix_in/suffix_out(b,id)` 接 1-based 既有点映射，分别返回汇集出口或分发入口。长度 w 的单方向链新增 max(w-1,0) 个点、两倍边，索引 O(w)，定位 O(1)。`pre[0]` 和 `suf[w+1]` 为 0；空序列传 `VI{0}`。只建需要的方向，多组反状态直接各建两条分发链。
- 线段树：`SegLinks<W,In,Out>(b)` 的 In/Out 默认都开启，单方向可关闭不需要的表。`build(id)` 按局部位置映射，`build(src,dst)` 支持汇集与分发使用不同状态点；双映射要求两方向均开启。`in_cover(l,r)`/`out_cover(l,r)` 返回 O(log w) 个全局节点，`l>r` 返回空。每方向新增 w-1 个辅助点、2w-2 条边，索引约 8w B。
- 树上倍增：`TreeLinks<W,In,Out>(b)` 接 `build(lca,id)` 或 `build(lca,src,dst)`；树点只用于外部 dep/fa/lca，id 决定图点。`in_cover(u,v,lca)`/`out_cover(u,v,lca)` 返回四槽数组，未用槽和断连均为 0。森林必须与建表时相同，定位 O(T+log w)，原树边不自动加入。每方向最多 w*floor(log2 w) 个辅助点及两倍边，索引约 4wL B。

所有映射都为 1-based 且指向同一上下文中已经分配的非零图点，可以非连续、重复，也可以指向已有中继。结构 build 只追加骨架并重建自己的索引，不删除旧图边。输入数组和组内索引销毁后，已建边保留。不同组、不同方向的映射互不影响；不能把源状态与目标状态强行共用一个叶子。

`b.link(src,dst,w)` 遍历两个覆盖容器的全部元素，忽略 0，解释为源集合到目标集合的全连接。任意一端只有一个有效入口时直接连到另一端的全部入口，不新建中继；两端均有多个有效入口时新建一个中继，汇集出口到中继为零权，中继到分发入口为 w。任一集合空则不改图、不耗预算；显式 `new_node()` 总会申请一个点。复杂度 O(|src|+|dst|)，权值只计一次。跨链、区间、树路径都用同一接口，不增加各种跨结构成员函数。调用方负责传入正确方向、同一上下文的覆盖。

旧 `PrefixGraph`/`SuffixGraph`/`PrefixSuffixGraph`、`SegGraph`、`TreeGraph` 共用上述内核；原构造参数、g/tot、连边方法和 build 清图语义保留。它们带有内部引用，禁止拷贝和移动；需要多组共享图时直接使用新接口，不经旧封装。旧第三参数仍只预算手动中继，新上下文第一参数则预算全部图点，不能混用两种容量公式。

P6378 用法是在一个 `b` 中为每组负状态构建前后缀分发链，正状态分别连接排除自身的左右入口。全图跑 SCC，只检查原变量的正反点；压缩辅助点不额外配取反点。“恰好一个”放宽为“至多一个”仅因本题补选不会破坏覆盖约束，不提供错误的通用 exactly-one 接口。

验证保留原三份兼容测试，新增共享图独立套件覆盖三种边权、任意映射、多组、源目标分离、单方向、跨结构、空段/断连/预算复位，并用原问题穷举核对 P6378。当前结果从[验证明细](../../verification/details.md)读取。所有骨架都不保持路径计数或共享容量的网络流语义；前后缀链深 O(w)，现有递归 SCC 的百万规模栈和整条流水线内存仍须另验，建图压力通过不代表该下游问题已解决。

### 竞赛选型与代价

当前选择是保留共享图和映射，控制抽象层数，不再增加覆盖类型的组合方法。建图内核和 2-SAT 的真假推导分别学习；旧单结构封装用于已有调用，新题优先学习共享上下文与所需方向，不必同时记两套接口。模板通过已登记测试不等于每个规模和内存限制都适用。

- 分组互斥或编号前后缀关系优先用链，组长总和 S 的单方向骨架为 O(S)；P6378 用两个分发方向。小组的展开本来很少时可直接写蕴含边，没必要强行压缩。任意区间再用线段树，不能用全局前后缀代替组内范围。
- SegLinks 用 O(n) 骨架换取每个区间 O(log n) 个入口，是一般区间连边的默认选项。多组只保留各自索引；单向题关掉另一方向。cover 返回 vector 会有分配常数，当前是接口简洁的明确代价；没有性能证据时不加入第二套回调或固定容器接口。
- TreeLinks 的优势是每路径最多四个入口，代价是 O(n log n) 骨架；查询定位仍为 O(T+log n)。对 n=200000 的链，双向骨架有 6475750 个总点、12551500 条零权边；按实际点边、Empty 边和两份编号表估算已约 222 MiB，不含外部 LCA、下游、操作边与分配器。保守容量预留还会更高，不能作 256 MiB 路径题的无条件默认。规模较大但操作较少时，先考虑直接展开较短路径，或 HLD 把路径拆成区间再接线段树建图：骨架 O(n)，单次连边通常 O(log^2 n)；此处是选型比较，未新增 HLD 建图封装。
- `link` 的中继只用于双侧多入口的集合连接。单侧一个入口直接连边，避免每次多一个点、一条边及下游状态。两侧元素都多时保留一个中继，维持线性于覆盖大小的连边量；不为常数大小的个例继续增加分支。
- 2-SAT 的内存要合计 Graph、辅助点、SCC 及仍存活的输入索引。按 P6378 的 n=m=10^6、单组、上下文预留 4n 点和 2m+6n 边估算，当前 Graph 加 `SCC(tot)` 的容量预算已约 259.4 MiB；若 a/neg/pre/suf 四份数组仍存活则约 274.7 MiB，还未计递归栈和分配器。这是按容器字段推算的预算，不是 RSS 实测。只改成非递归 SCC 并不能自动解决该内存问题；应先按目标限制收紧生命周期、状态表和存储再验整题。

当前单侧入口直接连边，TreeGraph.build 计入索引及临时映射空间；保留已经验证的压缩机制。后续优先级是由实际题目驱动下游栈/内存处理，或有基准证据时消除区间覆盖分配常数，而非继续扩充建图接口。
