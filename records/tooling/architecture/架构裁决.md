# 库减负：给 GLM 5.3 的架构裁决

结论：采纳自动生成总览，保留现有测试体系；先消除人工重复登记，不扩建质量评分系统。此次完成架构决策，生成器实现另作一个范围。

## A：总览自动生成——采纳方向，修正信息含义

目前的 `run_checks.ps1` 能确定 catalog 条目、实际源文件、对拍文件和直接 include 关系；它不能仅凭这些信息确定暴力是否独立、所有接口是否被调用，更不能确定多个平台都通过了 sanitizer。

已有实证也要求改口径：`.ci-results/misc-windows/summary.json` 明确是 `sanitize: false` 和 `-O2`；Linux 对应报告才带 sanitizer 参数。现有 summary 没有源码及传递依赖指纹，不能可靠绑定当前脏工作区。纯文本笔记没有编译冒烟结果。

因此将两件事分开：

1. **总览展示当前测试资产关系。** A/B/C 可以保留熟悉的导航形式，但标题必须明确不是可靠性等级：A 有直接引用的对拍资产，B 未发现直接引用，C 纯文本笔记。豁免的 C++ 文件单列并展示关系，不因没跳板就降为笔记。直接 include 不等于行为覆盖；所有“赛场主力可用”“双平台 sanitizer 通过”的自动推断取消。
2. **实际验证结果仍看运行报告。** 平台、编译器、参数、范围和 PASS/FAIL 按原始报告解释。第一版不把旧 PASS 合并进总览，不新增证据数据库，不用 HEAD 冒充未提交源码版本。若以后确需“当前版本通过”的总览，再独立设计源码、测试、依赖和参数的指纹绑定。

历史深检、重构期对拍和 🔧/💎 标记属于历史事实，留在 `sweep-history.md`；不能成为源码更新后仍自动继承的信用。生成器上线前，把旧总览完整归档一次，避免丢掉条目或手工备注。

### 实现形态

- 独立命令 `scripts/make_reliability.ps1`，默认只重建 `rules/reliability.md`；`-Check` 在内存生成并比较，过期则失败，不写文件、不运行编译。
- 共用事实收集函数放 `scripts/check_inventory.ps1`，从现有 runner 的目录/catalog/include 关系收集部分抽出。runner 与生成器使用同一份映射；不另维护第二份“模板 → 套件”字典，不解析终端 `[TEST GAP]` 文本来驱动生成。
- 现有 scaffold 校验的失败条件保持不变；`check_runner.ps1` 的假仓库要一起携带新 helper。展开器的事务、状态和预处理支持边界与资产统计无关，不把它们接进测试 runner。
- 普通测试运行保持只生成运行报告，不悄悄改跟踪中的 Markdown。CI 在普通作业增加 `make_reliability.ps1 -Check`；目录/测试引用变更后只需本地重新生成一次。
- 输出按 catalog 顺序及规范相对路径稳定排序，不写时间戳、绝对机器路径和易变耗时。结构变化才产生 diff。
- 总览要能定位到具体文件和测试文件；无法从静态关系确认的事项显示“未确认”，不用一个合成分数掩盖未知。

### TEST GAP 的裁决

保留提示，文字继续明确“未发现直接测试 include”。它是待办线索，不是失败门禁，也不等于“完全没被运行”。总览与提示共用关系映射；不为清空黄牌创建只 include、不校验结果的假测试。不引入传递 include 的“覆盖率百分比”。

### 最小验收

验证增加/移除直接引用、同名不同路径、catalog 笔记与豁免、零重复生成 diff、`-Check` 不写文件且过期失败；旧表每项均能在新导航或历史归档定位。复跑 runner 的 9 项自检，确认缺 catalog、错跳板、零匹配等仍会失败。此范围不重扫未改动的算法模板。

## B：规则分卷冻结——采纳为默认约束

当前六个文件职责足够：协作契约、坑位、工作流、生成导航、活跃板、历史证据。新条款优先放入对应文件，不再增加第七份 Markdown。不要为了凑数量把不同职责重新揉成一个巨型 rule；将来有无法归属的真实需求再讨论例外。

实施生成器时，同步把 `rule.md` 中“动模板或对拍后手工同步等级行”改为“关系变化时运行生成器；CI 校验生成物”；删除人工维护责任，保留原来的测试纪律。不要同时扩写第二份流程规范。

## C：历史压缩——采纳，保留可审计的事实

允许按同一范围合并重复进度和过程性留言。必须保留问题/修复结论、验证环境和范围、结果、证据位置，以及未解决分歧；不能把 Linux sanitizer + Windows O2 压成“双平台 sanitizer”，不能把仅执行测试压成接口已深检。

没有证据的旧结论标注“历史转录、未复核”，不要补写通过结果。暂不做历史压缩脚本，先用明确的编辑规则完成去重；不以压缩为由删除唯一反例或争议记录。

## 分工和下一项

展开恢复已完成并移档。下一项仅是“总览自动生成及共用关系映射”，触及 runner/helper/生成器/自检/CI 和相应规范引用；不与算法补强或历史大压缩同时领取。GLM 可按本裁决准备实施；实施者先在状态板署名领取，另一方随后按上述最小验收复核。
