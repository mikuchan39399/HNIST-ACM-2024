# zoi 展开与恢复实施记录

仓库：`F:\c++\my_code\HNIST-ACM-2024`。范围仅为头文件跳板、依赖展开、恢复及配套测试；未提交或推送。

## 已实现

- 展开后新增块外 include，可直接再次 expand；改 solve 后 restore 会保留修改。
- 每次从紧凑源码重新解析依赖，纯跳板穿透到母版后按完整路径去重。有守卫的钻石/循环依赖只输出一次，无守卫文件保留重复包含语义。
- 状态改为 `A.zoi.state.json`。无变化的二次展开不重写源码；依赖内容更新会报告实际路径并重新生成。
- 生成块被改动、标记损坏会明确报错。`forget` 保留当前代码，移除管理标记和状态；`restore -Force` 才会丢弃修改恢复快照。
- 写入使用可恢复事务与每题独立锁；中断后若源码又被修改，不覆盖。批量恢复一题失败不妨碍其他题。
- 旧 `.zoi.cpp + .zoi.sha` 指纹吻合时自动迁移；旧修改冲突、缺 SHA、缺源文件与未知临时文件均保留现场。

## 日常用法

在仓库根目录运行，操作前先保存编辑器：

```powershell
./scripts/zoi.ps1 expand F:\比赛\A.cpp
./scripts/zoi.ps1 status F:\比赛
./scripts/zoi.ps1 restore F:\比赛\A.cpp
./scripts/zoi.ps1 restore F:\比赛
```

新增 include 和题解修改放在 `// zoi:begin ...` / `// zoi:end ...` 生成块外。可以删除完整块来移除 include；不要仅删标记、留下正文。

直接改了展开的模板正文且想保留它时：

```powershell
./scripts/zoi.ps1 forget F:\比赛\A.cpp
```

此后文件作为自包含代码使用。状态文件请与题目源码一起保留到 restore 或 forget 成功，不要提前手删。

## 支持边界与目录清理

支持标准 include guard 和文件开头的 `#pragma once`。条件分支内的本地 include、宏式 include、`#undef`、反斜杠续行、块注释拆开的本地 include、无法解析的本地路径，均在写入前拒绝；标准库 `<...>` include 原样保留。符号链接别名暂不承诺去重。

展开器本身不创建存档目录。正常 restore/forget 会删除本题状态和事务文件；未知历史目录没有擅自删除。`.zoi-checks/expand-test-*` 是这次测试刻意保留的夹具和日志，含模拟的孤儿备份；安装器的 `settings.json.zoi.bak` 另属安装配置备份。
