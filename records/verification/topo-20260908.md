# 拓扑排序多测初始化修复

2026-09-08。P9520 双层 TreeGraph 预留约 852 万个图节点，TopoSort 每轮复制全部入度，使大量小测试也承担大容量的初始化开销。

## 改动与回归

- `build(g,n)` 改为只复制入度的 `0..n`，时间为本轮 O(n+m)，原图不变；空图返回 true，两个容器仍保留历史容量。
- 既有 `graph_check` 新增 8520710 点预留容量、连续 1000 组 0 到 240 点回归，覆盖链、重边、自环、回边及反复大小切换。用独立三色 DFS 判环，检查序列、原图入度和副本有效范围，不使用机器相关的耗时断言。
- 新回归在旧模板上触发副本范围断言；修复后通过。既有 `completed_graph_stress_check` 保留 20 万实际点数的大/空/单点/大验证。
- 接口注释、Usage、rule、用户功能表和验证登记同步；两个现有套件自动进入普通与 sanitizer CI，无需修改工作流。

| 同上 | completed_graph_stress_check，无参数 20 万规模 | PASS，执行 31.101 秒 |

Windows 命令为 `scripts/run_checks.ps1 -Filter graph_check` 和 `-Filter completed_graph_stress_check`；前者按子串额外选择两份优化建图套件。自动证据为 [图论与优化建图](runs/2b8807a357bb444588d34c20c8676839.json) 和 [20 万规模](runs/64afa4d63e01401bbd454175691fa0d0.json)，两层验证表已重新生成。

Linux 分别编译并无参数运行这两个真实套件，参数为 `-std=c++20 -O1 -g -Wall -Wextra -Werror -UNDEBUG -fsanitize=address,undefined -fno-sanitize-recover=all -fno-omit-frame-pointer -D_GLIBCXX_ASSERTIONS`，`ASAN_OPTIONS=detect_leaks=1:halt_on_error=1`。[专项原始结果](topo-sanitizer-20260908.json) 保存编译器版本、返回码、输出、依赖哈希和运行前后稳定性；这份专项 JSON 不冒充 run_checks 的自动导入格式。
