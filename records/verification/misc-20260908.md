## 哈希选择与来源

[custom_hash](../../algorithms/杂项/防卡/哈希防卡.cpp) 从时钟盐加 SplitMix64 改为 SipHash-4-8，保留类型名与整数调用，补字符串原始字节和两个整数的有序编码。每对象保存两个 64 位密钥字，默认构造从 `random_device` 经整数分布取得；拷贝保持密钥，固定密钥构造仅用于对拍。

选择依据为 [作者的项目说明](https://github.com/veorq/SipHash) 与 [原论文](https://cr.yp.to/siphash/siphash-20120727.pdf)：SipHash 面向短消息的带密钥伪随机函数，设计用途包含防哈希洪泛；2-4 是默认版本，4-8 是作者提出的保守版本。采用 4-8 是本次防卡优先的取舍，不声称它是所有约束下唯一“最强”方案，也不把轮数翻倍解释成防护概率翻倍。

防护依赖密钥熵与保密性。标准 `random_device` 的实际熵取决于实现，本次不宣称跨所有平台都具有相同安全随机源；没有回退到时钟或 MT 冒充秘密随机密钥。64 位输出仍有碰撞，哈希桶还会进一步取模；需要确定性最坏复杂度时应使用 map/set 或排序。固定密钥用例及少量默认构造的差异检查不能证明密码安全。

独立参照使用作者仓库版本 `32d067603b93b47828700880649198e0bfbbcffa` 的 C 实现，保留于 [reference/siphash](../../algorithms/杂项/对拍/reference/siphash)。`siphash_ref.h` 将上游 `siphash.c` 改文件名，并在提交前去掉一处注释行尾空格，执行代码未变；`siphash.h` 原样保留，官方 64 个 2-4 向量按同值小端整数存储。原作者署名、CC0 许可和来源说明随正式对拍保留，不进入赛场模板或手册。

## 修复与接口

| 条目 | 实际变化 |
|---|---|
| i128 | 旧读入在有符号域累积绝对值，合法 -2^127 触发 UBSan signed integer overflow；现用 u128 累积并安全还原负数。u128 仍只是别名，本文件未新增无符号流重载 |
| rnd | 原 `uniform_int_distribution<bool>` 编译失败，字符类型也不宜直接作为该分布参数；现提升至 LL/ULL 再转换。旧 [-DBL_MAX,DBL_MAX] 产生非有限结果，现用 generate_canonical 与 lerp 并处理半开上界，支持显式传引擎复现 |
| utils | fast_io 加 inline，修复双翻译单元的 multiple definition；z_fill_n 用 size_t 计算 n+10，保持下标 0 起填余量的既有行为。补 string_view/bit/unordered 容器公共头与完整 Usage |
| Dcr | 补 clear 保留容量，明确所有输入元素都参与、排名 1-based；size/逆映射要求已 build，追加值使旧排名失效；保留排名查询自动 build |
| Misra–Gries | 保留原候选抵消与二次核验机制，补守卫、公共依赖与完整 Usage；返回真实频次严格超过 floor(n/k) 的不同值，顺序不保证，适合小 k |
| custom_hash | SipHash-4-8、每对象密钥、整数/字符串/整数对；旧公开 splitmix64 助手不再提供，库内未发现其现役调用方 |

[旧版反例证据](stress/misc-probes-20260908.json) 含 i128 溢出、bool 编译失败、浮点大区间非有限结果和 fast_io 跨翻译单元重定义。反例运行在 task 内复制的旧源码中，没有覆盖新模板。未知非法 token、越界整数、NaN 端点等不扩展为异常解析功能。

## 默认套件覆盖

- [hash_check](../../algorithms/杂项/对拍/hash_check.cpp)：先用官方 64 个 2-4 向量校验参考路径，再用作者 4-8 参考实现对比 4000 个随机密钥及 0..4096 字节消息；覆盖空 string_view、8 字节边界、255/256/257 长度、百万字节、内嵌 NUL、高字节、整数极值和整数对编码。容器 20万—0—1—257—20万，map 独立核对修改/删除/查询，含复制、移动、rehash、2 万个长前缀字符串、整数对集合。
- [tool_core_check](../../algorithms/杂项/对拍/tool_core_check.cpp)：i128 硬编码完整边界，独立二进制逐位转十进制核对一万随机 128 位，另验十万前导零、二十万连续值读写及 EOF 保留值；utils 逐项检查别名、极值、方向、二十万长度的填充余量和尾部保留；Dcr 用 set/map 独立生成排名，二十万多形态及字符串/整数对、多测与副本隔离；Misra–Gries 三值域长度 0..8 全枚举、一千随机序列和二十万长度 k=2/3/8/32 的退化形态，以完整 map 频次表作答案。
- [rnd_check](../../algorithms/杂项/随机数/对拍/rnd_check.cpp)：16 类原生整数含 bool/字符的完整范围、相等端点；float/double/long double 的大异号端点、次正规、相邻浮点和半开上界；自传同种子引擎复现，常零/全一引擎边界；保留百万整数分桶并补三类浮点各二十万分桶。分桶阈值是宽松冒烟，不是均匀性证明。
- [utils_local_check](../../algorithms/杂项/对拍/utils_local_check.cpp)：开启真实 LOCAL，捕获 cerr，逐字核对多参数 debug 和 1-based debug_array。
- 原 misc_check 的离散化、哈希容器、rw、单调队列/栈组装回归保留。新三份与增强的一份均为无参数 `*_check.cpp`，自动进入既有普通与 sanitizer CI。

正式 Windows `hash_check` 输出：[哈希实测日志](stress/misc-hash-windows-20260908.txt)。构造的 5000 个步长键使本机默认整数 hash 最大桶长为 5000；新版四个固定测试密钥的最大桶长为 6、6、7、8。该阈值仅约束固定夹具，不承诺任意输入的最大桶长。
