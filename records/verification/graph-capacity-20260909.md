# 图论大容量对象与小规模多测检查

2026-09-09。检查目标是拓扑排序曾出现的“每轮处理本轮小图，却复制或清空全局预留容量”，并核对 Graph 省略边预留时的扩容与复用。

## 范围与结论

catalog 现役图论代码共 33 份；用户明确排除欧拉相关四份旧模板，最终范围为 29 份。25 份属于统一 Graph 体系，另外三份备用 LCA 使用旧数组接口，Floyd 保留旧独立 main。笔记、例题及弃置实现不作为此次验收对象。

| 范围 | 静态检查结论 |
|---|---|
| Graph | 构造分配点表；clear 只遍历 used 和清掉实际边；edges.size() 是当前半边数，不是预留容量。默认拷贝整个 Graph 按完整点状态复制，是显式拷贝成本。 |
| SCC、EBCC、VBCC、BCT | init 按本轮 n 清工作表，派生图按上轮实际用量 clear；缩图扫描本轮点/边/分量。 |
| 主力 DFN LCA、HLD LCA、HLD | 构造分配最大容量，init 与建表按本轮 n；没有从 Graph 复制整容量表。递归深度限制仍保留。 |
| 两份虚树 | 清上次实际虚树，工作点集按当前关键点数量，不遍历原树全部预留节点。 |
| 两份直径、中心、重心 | 工作数组按传入 n 赋值，遍历实际树；清理旧答案不等于扫描预留容量。 |
| 四份单源最短路、两份全图判负环 | 初始化按本轮 n，遍历实际邻接边；队列和堆按本轮内容处理。原算法的最坏复杂度不因容量检查而改变。 |
| Kruskal、Prim | 工作表按 n 或当前 edge_cnt 创建；不按边数组 capacity 排序，不复制 Graph。 |
| SegGraph、TreeGraph | 构造分配原点/中继预算，build 按本轮原点重建，旧图清理按实际用量；边可从零预留扩容。 |
| TopoSort | 前一轮已修为复制 0..n 入度，本轮保留并加入组合容量回归。 |
| 三份备用 LCA | 使用原生前向星数组或自管图，未发现按外置 Graph 容量复制；倍增/欧拉序旧版没有主力模板的统一 init 接口，不能直接套用其多测流程。未借本次检查改造旧接口或宣称其完整正确性。 |
| Floyd | 发现整张固定矩阵 memset；改为仅初始化 dp[1..n][1..n]。仍是 N=110 的独立 main，不扩展题意、权值范围或重写成 Graph 引擎。 |

统一 Graph 体系中，除了已修复的拓扑，未发现第二处同类整容量复制。Floyd 原来每次清 110×110×4 = 48400 字节，修复后本轮矩阵初始化为 4n² 字节；这处当前规模很小，不把它描述成与 P9520 同量级的耗时缺陷。

## 可执行回归

`graph_capacity_check.cpp` 直接引用 25 份真实模板。对象每组只构造一次，原点预算 200000、每轮实际 1 到 33 点，四组各 1000 轮。外置 Graph 省略边预留，包含靠近容量上界的点清理、实际边数组扩容、负环后复位、空/重复关键点、派生图重建与中继预算复位。

独立依据使用星形图的距离、生成树总权、强连通分量、桥、点双、直径、中心和重心闭式答案；压缩图检查已知点数和拓扑可行性。部分工作表设置高位哨兵，核对本轮 init/run 不清无关尾部。它检查的是特定容量场景，不代替任意图语义对拍、深链或最大实际图规模验收；一次构造的空间成本仍然存在。

`floyd_capacity_check.cpp` 重命名并调用真实旧 main，通过流输入输出执行 304 组非负无向图。逐源朴素 Dijkstra 作独立参照，含自环、重边、断连及 109-1-109-1 复用。dp[0][0] 哨兵在旧版被整表清空，新增回归先触发断言；修复后保持且所有答案通过。负边、负环和大权溢出不在本次范围。

## 调用边界

- `Graph<false, LL> g(MAX_N)` 支持只给点容量；max_m 是可选预留提示，不是边数上限。
- 点表不会随 add 扩容，点编号仍须落在构造容量内；所有存活对象的总内存仍要预算。
- 全局图每轮 clear；下游按契约 init(n) 或 build(g,n)。首次默认 n 可能是构造容量，不传真实 n 属于调用范围问题。
- 清理上一轮实际图、结果或堆栈是必要成本；只要不是每个小测重复处理未用的最大容量，就不属于本次缺陷。
- 不能在扩边期间持有旧 Edge 引用；边编号保持稳定，vector 引用可能因重分配失效。
