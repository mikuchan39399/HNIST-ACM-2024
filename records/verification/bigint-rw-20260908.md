# BigInt 与 rw 深度对拍及 Usage

日期：2026-09-08。执行者：Codex。用户要求深测两个工具内核并写好 Usage，注释次要。两项现行设计均为固定引擎，未调整分类、未新增 README、未提交或推送。

## 修复

| 位置 | 修复前的实际问题 | 处理 |
|---|---|---|
| BigInt 多块除法 | `1000000000000000000 / 9999999999` 打印 `0100000000`，且与整数 `100000000` 比较不等 | 返回商前清除高位零，补四种符号及后续自除/归零反例 |
| BigInt `to_i128()` | 合法的 `-2^127` 触发范围断言 | 用无符号绝对值累积，按正负分别设上限；安全还原最小负数 |
| rw `read(double&)` | 100 个前导零后接 `1.25` 越过固定 `char[64]`；旧版 UBSan 报 `index 64 out of bounds for type 'char [64]'` | token 改为动态字符串，覆盖超过 4 MiB 的合法浮点文本 |
| rw `write(double)` | 最大有限 double 的定点表示被 64 字节数组截断，只写出前 63 个字符 | 384 字节容纳全部有限 double 的六位定点输出 |

另外补齐 bool 的无符号辅助类型，以及字符串/字符读取对竖向制表符、换页符的识别，覆盖六种 ASCII 空白。整数/浮点输入仍要求合法 token，不扩展成异常输入解析器。

BigInt 保留原算法，只补必要契约。旧 Usage 中不能持久保存的 C++20 constexpr 大数对象、未经限定的耗时承诺和未验证的大数图边权组合已撤去。两份新 Usage 均为完整 `main`，使用本库正式 `bigint.h` / `rw.h` 跳板；不靠省略号补齐代码。

## 使用限制与交付

BigInt 原生构造接受不超过 64 位的整数及有符号 i128；u128 用十进制字符串。除数非零、开方非负、幂指数非负、`mod` 模数为正 LL，`to_LL/to_i128` 的结果必须落在目标范围内。乘除仍有规模成本，测试通过不代表任意位数均能在时限内完成。

rw 输入为合法空白分隔 token，整数须在目标类型内；double 输入十进制/科学计数法，输出固定六位，不是无损浮点序列化。同一标准流不混用 cin/cout、scanf/printf；正常退出会刷写，不承诺异常终止或交互输入场景。
