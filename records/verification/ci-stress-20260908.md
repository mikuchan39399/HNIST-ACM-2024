# 2026-09-08 图论专项 CI 入口修复

提交 ceb8a1d 的 [CI #38](https://github.com/mikuchan39399/HNIST-ACM-2024/actions/runs/34229193838) 共八个作业，六个通过，两个图论专项压力作业在编译前失败。普通回归、全库 sanitizer、两种数值深测、部署和手册均通过；本次只处理失败入口，不改算法实现。

## 原因与修复

- `completed-graph`：main 的自检分支给局部变量 `suite` 赋值，遮蔽导入的同名路径定位函数，普通分支调用时报 `UnboundLocalError`。定位函数改用明确别名 `find_suite`。
- `lca-vt`：依赖快照用正则扫描全文，将 utils 尾部 Usage 注释内的 `#include "utils.h"` 当作真实本地依赖，随后在源码目录查找不存在的 utils.h。扫描前按 C++ 字面量和注释边界屏蔽注释及 raw string，保留实际引用和条件分支；真正缺失的本地依赖仍报错。
- 旧 `--self-test` 只检查结果分类与子进程，没有执行 profile 启动和快照路径。新增两项自检：验证真实依赖与示例区分、依赖修改使哈希变化、真实缺失失败；两种 profile 均走真实 main 参数解析/定位/快照/报告，仅替换编译执行并断言编译失败不能成为通过。既有 CI 自动执行扩充后的自检。

## 本地复验

环境为 WSL Ubuntu 20.04、Python 3.8、GCC 13.1；没有把 Windows 执行结果当成 Linux 证据。

| 命令/范围 | 结果 |
|---|---|
| `python3 scripts/check_lca_vt_extreme.py --self-test` | 4 项通过，含两种 profile 的启动分支；输出中的人为 FAIL/TIMEOUT 是负例 |
| `--profile lca-vt --compiler g++-13` | 普通百万点浅树、256 MiB 栈百万点深链通过；sanitizer 的两个 20 万点默认栈探针均为既定 STACK_LIMIT；[原始结果](stress/ci-fix-lca-vt-20260908.json) |
| `--profile completed-graph --compiler g++-13` | 普通和 ASan/UBSan 的 20 万点浅树、深链全部通过；[原始结果](stress/ci-fix-completed-graph-20260908.json) |

两个完整 profile 均生成报告且前后源码快照一致。STACK_LIMIT 仅表示指定递归实现超出探针的 8 MiB 栈，不是该深链用例通过；没有改动压力规模、超时和允许状态。
