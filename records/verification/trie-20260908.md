# Trie 双件深度对拍与 Usage

日期：2026-09-08。范围为普通 Trie、可持久化 Trie 及原有两套对拍；保留其他工作区改动，未提交或推送。

## 修复与接口

- [普通 Trie](../../algorithms/字符串/字典树/字典树.cpp)：接口保留，查询补 const，clear 只重建零根，后续开点整结点初始化，避免逐个清零旧池。去掉并不存在的“删除单词”说明，明确不支持删除、空串与重复次数。
- [可持久化 Trie](../../algorithms/字符串/字典树/可持久化字典树.cpp)：字符串插入改为循环复制路径，保持每次串长+1个新结点和历史版本不可变；数值插入递归仍至多65层。多根 max_xor、count_prefix、lcp_len 的中间计数统一 LL；单根前缀查询直接走树，省掉临时根向量。
- 容量断言先比较再递增，持久化 reserve 用 size_t 加一，避免预算表达式自身的 int 加法溢出。普通 cap 包含根；持久化 cap 不含空哨兵，整数插入每次 HB+2 个点。
- 两份保持固定引擎、原类型/方法名与短名跳板，不新增算法 README。源码尾部 Usage 均为完整可运行程序，说明字符串、01-Trie、区间根差、历史分叉和第 k 大；树路径给出根差公式及前置条件。
- 修正旧对拍随机数构造：先以 ULL 拼接两段随机数再屏蔽符号位，避免原先有符号左移后相加可能溢出。测试生成器同样接受 sanitizer 检查。

`lcp_len` 是查询串与集合中某个单词的 LCP 最大值，不是所有单词的共同前缀。字符串与数值接口不混用；整数及查询 x 均非负且放进选定 HB+1 位；差集按每个值的出现次数非负。单版本元素数在 int 内，多根正负侧各自的计数和在 LL 内，xs.size() 在 int 内。clear 保留容量，但旧句柄全部失效。

## 旧版反例

[隔离反例诊断](stress/trie-probes-20260908.json) 保存旧源码副本的实际执行结果：

| 反例 | 旧版结果 | 修复后验证 |
|---|---|---|
| 20万字符长串，Linux GCC13 O1 ASan/UBSan，栈限制1 MiB | ASan stack-overflow | 同样1 MiB栈下完整默认套件通过 |
| 7万次插入 `a`，4万个相同根查询前缀 | `70000 + 2147460000` 的 int 溢出 | 返回2800000000；减去39999个根返回70000 |
| 7万次插入1，4万个相同根查询最大异或 | 根总数累计同样 int 溢出 | 原集合及抵消后返回1；完全抵消返回-1 |

20万长串旧版在本次最初的 Linux 默认栈下通过；问题是线性递归栈依赖，不把它描述为所有环境必崩。1 MiB 栈对照用于确认消除了串长相关的递归，不更改默认 CI 栈配置。

## 默认自动覆盖

[trie_check.cpp](../../algorithms/字符串/字典树/对拍/trie_check.cpp) 的原有300组级字符串、整数、区间与第 k 大对拍保留，新增：

- 字符串 K=1/2/10/26/62，每种100轮、每轮80次任意历史分叉；完整快照直接扫描前缀和 LCP，含空串、多根重复与抵消。
- 数值 HB=0/1/10/30/62/63，每种100轮、每轮80次分叉和80次查询；独立沿 parent 枚举版本树路径值，小笛卡尔积全排序核对每个 k。两类共88000次新增分叉，每次逐结点核对旧池未变。
- 普通与持久化20万长串三轮清空重建；单词、真前缀、缺失后缀、空串与 LCP。持久化长串与空串恰好用满200002个点。
- 20万个连续整数，两轮完整清空重建；普通 Trie 每轮80次全候选扫描，持久化每轮80个大区间扫描及第1大。HB30用满640万个结点，节点池有效数据76800000字节，另算根数组及其他对象；这不是测试进程的峰值内存。
- 28亿多根累计、最终小计数和完全抵消；20万行乘20万列的0/1异或矩阵有400亿个配对，用独立闭式计数检查第200亿、第200亿+1、第400亿和越界位置。
- LLONG_MAX、第62位、空树/版本/差集、重复值、空 xs 和 k 越界继续保留。查询不分配持久化结点。

[trie_capacity_check.cpp](../../algorithms/字符串/字典树/对拍/trie_capacity_check.cpp) 覆盖 HB=0..63 全部位深每种10轮、普通预算1/4/65及持久化3/5点预算300轮复用。检查精确结点数、已预留地址不变、重复插入、空串复制根、cap=0空哨兵与两份重复 include。

所有算法正确性与规模用例都在两套无参数 main 中，既有普通和 sanitizer CI 自动发现。未把非法字符、负数、逐值为负的根差或不够的容量当成合法输入要求模板返回正确答案。
