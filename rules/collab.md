# 双 AI 协作契约 (GLM/Cline 铺底 × GPT/astra 善后)

- 分工: 铺底 = 日常开发/对拍/小修/收尾提交, 贴现有体系快速干;
  善后 = 审查边界、补独立反例、精简模板与注释。双方都以 rule.md 为最高
  规范, 本契约只是协作层, 不新增算法或码风条款。
- 断点续传: 善后者 token/时长有限, 每完成一个范围内的一件事就在
  rules/sweep-board.md 打勾并记录(提交号或结论); 中断后从板上续跑,
  禁重扫已勾范围。
- 粒度纪律: 一次只做一个范围内的一件事(如"AC自动机: 对拍"或
  "AC自动机: 打磨"), 完成打勾再取下一件; 不跨范围并行。
- 活跃区避让: 状态板上标 🔒(进行中+署名)的范围, 另一方不动其涉及
  文件; 全新独立文件不受限。铺底者收尾提交前必须过目 git status,
  只提交自己范围的文件, 不吞他人半成品。
- 分歧裁决: 两方对同一文件各有未合流改动时, 用户拍板; 板上留 ❌ 行
  写清分歧点与两案, 不擅自覆盖对方成果。
- 入口: Codex/astra 走仓库根 AGENTS.md; GLM/Cline 走 .clinerules\zoi.md;
  两条通道路由到同一份 rule.md, 谁也不私藏规范。
## 记录与交接

- 状态只设待办、进行中、完成、待裁决；进行中写执行者和涉及文件，不整库加锁。
- 一行只记一项工作，区分模板修改、测试补强、套件执行；只有运行过的环境才打勾。
- 记录日期、范围、修改或结论、测试入口及结果；有提交号就附，没有就写未提交。
- GLM 代记供接手者核实，不等同实测证据；发现误记直接更正，原记录留在历史。
- 代码或依赖变动后只重验受影响项；不重扫已验证且未变化的范围，也不把旧绿灯套给新改动。
- 暂停时记录下一步、已知失败和日志位置，解除自己已结束的锁；恢复后先读板再行动。
- “铺底者收尾提交”不自动构成 Git 授权；双方均遵守 rule 的用户授权约定。
